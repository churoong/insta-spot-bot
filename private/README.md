# 비공식 API 에이전트 (2026-10-27 사용자 결정)

⚠️ 인스타 이용약관 위반이라 계정 제한·정지 위험이 있다 — 사용자가 감수하기로 결정했다.
GitHub 러너가 아니라 **사용자 PC에서만** 돈다(데이터센터 IP에서 비공식 로그인은 거의 확실히 보안 확인에 걸린다).

## 처음 한 번
1. `.env`에 직접 추가: `IG_USERNAME=...` `IG_PASSWORD=...` (공개 저장소에 올라가지 않는다 — `.env`는 .gitignore)
2. `python private/login.py` — 2단계 인증·보안 확인 코드가 뜨면 여기서 입력. `private/state/session.json` 생성
3. `powershell -ExecutionPolicy Bypass -File private\install-task.ps1` — 로그온 시 자동 실행 등록
4. GitHub 저장소 변수 `PRIVATE_HANDOFF=1` — 이때부터 발행을 에이전트에 넘긴다(끄려면 변수 삭제)

## 하는 일
| 기능 | 언제 | 비고 |
|---|---|---|
| 발행 핸드오프 → 인스타 음원 + 위치 태그 릴스 | 모음집·큐레이션 발행 때 | 10분 안에 못 가져가면 GitHub가 공식 API로 발행(음원·위치 없음). 큐레이션은 나레이션이 있어 음원 안 붙임 |
| 스토리(게시물·위치 스티커) | 핸드오프 발행 직후 | 공식 경로 회차는 기존처럼 GitHub가 표지만 올림 |
| 첫 댓글 고정("🥇 1위 …") | 모든 회차 | 공식 경로 회차는 10분 주기 사후 처리 |
| 위치 태그 | 모든 회차 | 공식 경로 회차는 게시물 수정으로. 이름이 맞는 장소가 없으면 태그 안 함 |
| 자동 좋아요 | 하루 1회, 11~21시 무작위 | 음식 태그 최신 게시물 18~26개, 25~75초 간격 |
| 팔로잉 정리 | 3시간마다 최대 10명, 하루 30명 | `state/unfollow-approved.txt`에 있는 사람만. 후보는 `following_review.py`가 CSV로 뽑는다 |

| 식당 계정 태그 | 발행 때(공식 경로 회차는 사후 처리) | 계정 탭 검색으로 상호 일치 + 지역 일치(계정 이름·소개)인 계정만. 확신 없으면 안 붙임. 결과는 DB 캐시 |
| 오늘의 음원 | 하루 1회 집계 | 맛집 태그 인기 릴스들이 쓴 곡(제목·가수)만 세서 최다 곡. 못 구하면 `music.txt` |
| 우리 게시물 댓글 응대 | 10분 주기, 하루 30개 | 하트 + LLM 답글(존댓말·홍보 금지). 이모지만·'지도' 요청은 하트만 |
| 프로필 고정 | 하루 1회 | 조회 1,000+ 상위 3개 |
| 스토리 하이라이트 | 핸드오프 스토리마다 | 국물 · 면요리 · 동네맛집 · 맛집 |
| 타깃 좋아요 | 하루 1회 12~21시, 12~18개 | 팔로워 5만+ 맛집 계정 최근 게시물에 댓글 단 사람들의 최신 게시물 |
| 남의 게시물 댓글 | 하루 1회 11~20시, 8~12개, 3~8분 간격 | 맛집 태그 최신 게시물에 그 내용을 짚는 LLM 댓글. 같은 사람은 30일에 한 번. 생성 실패면 안 단다(템플릿 금지). 링크·해시태그·맞팔/팔로우 요청 금지 |

음원 검색어는 `music.txt`(인스타는 '유행 음원 목록'을 주지 않는다 — 요즘 곡을 직접 적어 두기).
차단 신호(보안 확인·활동 제한)가 오면 6~24시간 비공식 호출을 전부 멈춘다. 로그: `private/logs/agent.log`.
